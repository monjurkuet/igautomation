# Plan: Fix Known Issues, Remove Technical Debt, Harden Architecture

## Goal

Bring `igautomation` to clean SWE baseline: fix runtime bugs, eliminate fake/stub behavior or mark it safe, reduce dead/duplicated code, harden daemon/CLI/DB layers, improve tests so passing suite proves real behavior, and keep architecture maintainable.

## Current Verified State

- Source imports mostly resolve and CLI help renders.
- `uv run pytest -q` previously passed 180 tests, but one audit run timed out at 120s due slow browsing/daemon sleeps.
- `uv run ruff check src/` passes.
- `uv run ruff check .` has real test lint issues, not false positives.
- Recently added daemon split is useful, but surfaced unwired config and stub executors.

## Scope

Do in code, tests, docs. No Docker/CI unless separately requested.

## Non-Goals / Guardrails

- Do not make comment automation active by default.
- Do not delete user data, `.env`, DB files, or runtime local files.
- Keep public CLI command names stable where possible.
- Prefer small correct changes; refactor only after tests cover behavior.
- If removing legacy pieces, preserve import/export user flow or provide migration path.

## Decision Points Before Implementation

1. Legacy `SQLiteStore`:
   - Recommended: migrate `igx discover` to `AsyncDatabaseStore`, then rename/remove legacy SQLite store.
   - Safer alternative: keep legacy SQLite but clearly mark as deprecated and add migration tests.

2. Story/unfollow strategies:
   - Recommended: make honest no-op until real action implementation is verified. No fake DB logs.
   - Alternative: implement real browser actions now, but requires UI selector verification and stronger safety checks.

3. Comment strategy:
   - Recommended: keep disabled and remove from fallback plans unless `comment_enabled=True` with real implementation.
   - Alternative: keep registry entry but always returns `not_implemented`.

4. DB migrations:
   - Recommended: add migration tracking and preserve compatibility with existing local DBs.
   - Faster alternative: reset migrations around current schema only, but risky for existing databases.
