# Implementation Plan: Daemon, Cron, Cleanup, Architecture

## Goal

Bring `igautomation` to maintainable SWE standard by finishing missing daemon/Hermes cron features, removing dead/unused code and runtime artifacts, tightening daemon reliability, improving architecture boundaries, and making docs/tests match actual behavior.

Explicit exclusions from user:

- Do not add Docker compose or Docker restart policy.
- Do not add CI/CD scheduled triggers.

## Current State From Audit

### Existing strengths

- Package uses `uv`, `pyproject.toml`, `hatchling`, Typer CLI, Rich output, pytest, ruff.
- Core daemon exists: `src/igautomation/daemon/loop.py`.
- Human-like scheduler exists: `src/igautomation/daemon/scheduler.py`.
- Auto-analysis exists in daemon every 5 sessions.
- CLI daemon commands exist: `igx daemon start|stop|status|analyze`.
- Test suite collects 154 tests.
- Async database layer exists with migrations and core tables.

### Confirmed missing features

- Hermes cron integration is only planned in docs; `src/igautomation/daemon/cron_config.py` does not exist.
- No cron export/install/status commands exist.
- No systemd service file or service-generation command exists.
- No project-managed daemon YAML example exists.
- No PID safety/locking layer exists.
- Daemon fallback plans include strategies not dispatched by `DaemonLoop`:
  - `story_viewing`
  - `auto_unfollow`
  - `comment_engagement`
  - `own_account_monitoring`
- LLM planner prompt references fields missing from `_gather_stats()`:
  - `unanalyzed_count`
  - `story_candidates`
  - `unfollow_candidates`
- Multi-account config exists (`ports`, `account_rotation`, cooldown fields), but daemon `_connect_cdp()` only uses `cdp_port`.

### Confirmed technical debt

- `src/igautomation/daemon/loop.py` is too large at 1038 lines and mixes orchestration, strategy execution, LLM planning, cron-like analysis, DB cleanup, and CDP connection.
- `src/igautomation/cli.py` is too large at 937 lines and mixes top-level commands, daemon commands, DB commands, account commands, migration, and presentation.
- Broad `except Exception: pass` appears in daemon and DB migration paths, hiding failures.
- Async daemon still uses sync CDP/GraphQL/behavior functions; some are wrapped in executors, some remain direct blocking calls.
- `croniter` dependency exists but no active code uses it.
- `analysis/analyzer.py` imports `os` but appears unused.
- `daemon/loop.py` imports `SessionScheduleConfig` but does not use it.
- Daemon background start writes PID to `Path(cfg.db_path).parent / "daemon.pid"`; stop always reads `Path("daemon.pid")`, causing wrong stop behavior for custom DB paths.
- Background start does not verify stale PID, running process identity, duplicate daemon, or startup success.
- `daemon.pid`, `.env`, and `igautomation.db` are runtime/local files present in repo root; they should not be committed and should be ignored/removed from version control if tracked.
- README omits daemon usage, cron/service setup, multi-account behavior, and actual CLI surface.
- `docs/CODEBASE_KNOWLEDGE.md` is stale and contains outdated issue numbering/claims.
- Legacy `storage/SQLiteStore` still exists and is used by `igx discover`; likely acceptable as backward-compatible CLI output, but should be marked legacy or migrated deliberately.

## Non-Goals

- No Docker files.
- No GitHub Actions, GitLab CI, or scheduled CI.
- No destructive data migrations without backup path.
- No Instagram login automation.
- No broad rewrite to fully async CDP unless needed for correctness.

## Risk Notes

- Refactoring `loop.py` and `cli.py` can break imports; keep public API and command names stable.
- Real CDP/Instagram behavior cannot be fully tested in unit tests; use mocks plus one manual smoke run if Chrome is available.

- All fallback strategies either implemented safely or explicitly disabled in config and not chosen by fallback.

- User-level systemd service render/install/uninstall exists; no Docker/CI added.
- Daemon PID start/stop/status works for default and custom DB paths.
- Daemon lifecycle reliably closes DB/CDP and records terminal status.
- Multi-account config is honored or documented as disabled.
- `croniter` is used legitimately or removed.
- Dead imports and unexplained dead constants cleaned.
- Runtime artifacts and secrets are ignored/untracked.
- README and codebase docs match actual code.
